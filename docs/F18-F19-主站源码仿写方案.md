## 3. F18：数据与声明式解释

### 3.1 支持清单

| 类别 | 首批实现契约 | 明确边界 |
| --- | --- | --- |
| 初值 | JSON 对象、有界缩进 YAML 子集、`<initvar>`；世界书 InitVar 条目和 `extensions.mvu.initvar` | YAML 标签、别名、任意对象构造不执行；JSON5 特有语法单独诊断，不伪称全部支持 |
| 默认值 | 识别静态 `z.object` 属性及字面量 `.default(...)` / `.prefault(...)` 子集 | 不加载/执行卡片 Zod 代码，不承诺任意 schema 验证/transform/refine |
| 更新 | `<UpdateVariable>`、`<JSONPatch>`、`<json_patch>`；JSON 数据和 `_.set('路径', 旧值, 新值)` 三参数形式 | 不执行 lodash 代码、函数调用、计算表达式或模型输出代码 |
| Patch | 数组或 patches/jsonpatch 包装；add/replace/remove/test/copy/move、delta、insert→add、move.to | JSON Pointer 转义、数组索引、from、缺失字段均校验；delta 只接受有限数字并保留值/描述元组语义 |
| 变量读取 | 完整路径和 stat_data 路径回退；`getvar` / `get_message_variable` 字面量参数及 defaults | 路径拒绝 `__proto__` / `prototype` / `constructor`；非法路径拒绝，不返回整个根对象 |
| 模板 | 文本、受限变量插值、字面量比较/真假判断、if/else if/else、可识别局部变量声明、`getwi` 字面量查询；MVU 双花括号读取/格式化宏 | 不支持循环、任意 JS、DOM、网络、eval/Function；局部声明真正传入解释环境 |
| 世界书查询 | 从本会话允许的世界书副本读取，不触发激活副作用 | 查询失败/未知模板保留原文并给出定位诊断 |

主站在有 `window.JSON5` 时会尝试 JSON5；分站当前没有该解析依赖。首批采用可验证的 JSON、引号字面量和 YAML 子集，不为“全兼容”临时拼接任意对象表达式解析器。JSON5 扩展需求进入明确诊断和后续兼容测试。

限额采用显式内部常量，不添加用户配置项：状态 1 MiB UTF-8；单个更新块最多 256 操作，超限拒绝整个块；模板输入最多 100,000 字符、输出 200,000 字符、256 节点、8 层条件。状态及路径遍历增加有界深度，具体边界随首批非法输入测试固定。主站状态上限实际用字符串 length 比较；分站按 UTF-8 字节计算，中文状态也遵循同一字节上限。

Patch 路径兼容主站方言：块内任一路径以 envelope 字段开头时，整块按 envelope 解释，否则相对 stat_data；不支持空路径整根替换。`display_data` 初始为 stat_data 副本，此后用于变更显示，add/replace 写对应值，delta 与 set 记录旧值到新值及原因，不能当成永远同步的状态镜像。带描述值 `[value, "description"]` 的模板读取仍是数组，标量需要显式取 `[0]`。

模板 `==/!=` 与 `===/!==` 均按严格比较处理，沿用主站语义，不采用 JavaScript 宽松转换。`_.set` 检查已有值类型兼容；Patch replace 可替换 JSON 类型，不把 set 的兼容检查套到所有 Patch 操作。局部声明首批支持字面路径 getvar、有限 Number(getvar)、默认字面字符串及可识别条件赋字符串；IIFE/`_.get` 等只能在列明的固定归一模式匹配后解释，其他语句诊断不支持。

**有意差异：更新块原子化。** 主站逐操作应用，失败项不会撤销同块前面成功项；分站先在副本解析/验证整块，块内任何非法操作都不应用该块，诊断列出原因。按文档顺序处理其他有效块；不回滚之前独立有效块。此差异必须列入兼容报告，不能宣称失败语义完全相同。`_.set` 的旧值参数用于兼容记录，不将其误当主站强制比较条件。

### 3.2 会话、消息与回复版本

沿用兼容数据外形 `conv.mvu = { version: 1, initial, current, initializedAt }`，以及消息上的 `mvuManualData`。`initial`、原始消息正文和人工覆盖是回放来源；`current` 是兼容输出的物化结果，不能单独证明历史有效。检查点、解析 AST、诊断缓存和运行实例放入非序列化运行表，不进入备份/同步。

人工覆盖新增稳定版本绑定 `mvuManualVersionId`：有选中回复 ID 时绑定该 ID，否则绑定 `base:<message.id>`；覆盖内容随 `responseVersions[].message` 一起保存/切换。首次捕获基础回复为正式版本时，将 base 绑定在同一候选内迁移到所捕获版本 ID；prepareResponseVersions 的匹配同时比较人工覆盖，不只比较 M1 正文 revision。版本切换必须连同 `secondMessages`、变量覆盖和后续状态一次可靠提交。

人工写入已有选中版本时，在同一候选内更新 live 消息及对应 `responseVersions[].message` 的覆盖字段；不能只改 live 消息，随后又复用尚未更新覆盖的版本记录。切走/切回必须恢复最近已确认的该版本覆盖。

编辑/续写生成不同正文的新版本时，不自动继承旧正文的人工覆盖；旧覆盖随原回复版本保留，新版本从前序状态和新完整正文回放，避免旧整份覆盖吞掉新更新。仅捕获同一正文的版本身份时迁移绑定，不把绑定迁移当作状态重新授权。

主站人工覆盖使用 `mvuManualSwipeId` 数字序号；本地 M3 使用 `selectedResponseVersionId` 和 `secondMessages`，而主站导出清理还涉及 `linkedMessages`。导入保留外来字段；只有能证明序号与实际选中正文/版本对应时才迁移覆盖。不能靠数组位置给不明覆盖绑定一个本地版本；无法对应时显示“覆盖版本未确认”，保留原数据。

初始化在新建会话、明确缺失初始状态或用户显式更换开场时进行；更换开场按所选内容重新建立初始状态并回放。采用主站来源优先级并记录初始化指纹；InitVar 专用世界书条目沿用主站初始化规则，不因其 disabled 而被普通世界书激活过滤排除。已有会话导入初始状态经验证后保留，不因公共角色卡/世界书后来变更自动重置历史。不新增“重置所有状态”功能。

开场版本另外保存 `responseVersions[].mvuInitial` 的独立副本：第一次捕获保存旧基线，新开场候选建立新基线，切回旧版本恢复对应基线。开场正文、conv.mvu.initial 和回放末态在同一可靠候选/commitPendingSnapshot 中提交；不能只替换开场消息而残留另一个开场的初值。

回放使用完整的当前选中历史，从 initial 开始，按助手主消息更新，然后应用对应人工覆盖。二段消息是展示材料，不再次驱动变量更新，避免同一回复二次计算；这是分站二段模型的明确约定。用户消息不执行更新块。重生成、续写、开场选择、编辑、删除、切换版本均从最早改变位置重新推导。

缓存签名使用初始状态指纹、消息稳定 ID、现有 M1 内容 revision、选中回复 ID、人工覆盖内容/版本指纹和上一个状态签名。**不改变 M1 消息身份算法，不把缓存写入 getMessageRevision。** 可以采用每 100 条检查点、最多 200 个查询快照的主站基线；缓存只是性能优化，清空后结果必须相同。

### 3.3 可靠保存与提示词接入

本地 [首次回复生命周期](../src/app/generation/52-generation-message-lifecycle.js)、[编辑](../src/app/chat/67-message-edit-helpers.js) 和 [删除](../src/app/chat/67-message-actions-ui.js) 目前存在“先改 live messages，再异步 persistState”的路径。只给 MVU 新增一个 save 调用不能满足失败保护。

首批必须把这些相关消息操作接入已有 [persistConversationMutation](../src/app/state/35-conversation-mutation-persistence.js)：构建候选 → 纯回放/验证 → 保存前核验 → 等待存储完成确认 → 再核验并合并本次变更 → 发布状态/事件和启动后续生成。失败保留已确认的正文、版本与变量。流式正文可以预览，但不进入有效 MVU，不提前触发变量事件；首次回复保存完成前不启动依赖其变量的第二阶段。

M3 的 [commitResponseVersion](../src/app/conversation/32-response-versions.js) 已有可靠保存；其候选 messages.slice 仍共享既有消息对象，因此回放必须纯函数返回状态，不能顺手在共享对象上写快照。生成 requestConv 新增 MVU 字段也必须是独立副本。提交校验包含目标会话对象、完整来源链、选中版本、initial 和人工覆盖，commitPendingSnapshot 同步本次成功字段；失败补偿不能恢复整个旧全局快照或删除等待期间的新聊天。

[发送入口](../src/app/events/70-events-init.js) 还需透传已有流式 completion 参数，避免把中断回复当作正式完成的状态更新。新聊天、导入会话和更换开场的 replacePlaceholders 明确传入 `{ conv }`，不能在活动会话尚未切换时读取上一聊天状态。续写对拼接后完整正文从目标之前的状态回放一次，不拿旧快照再累计同一批更新。

新聊天开场同样有确认边界：[registerNewConversation / renderNewConversationState](../src/app/conversation/59-new-chat-finalize.js) 当前先注册 live 再延迟保存。开场初值和更新块须在候选中准备，完成确认前不向后续请求发布有效状态；保存失败保留可重试的原始开场，不能把未确认初值当作已保存。

M2 提示词按以下顺序接入：从完整已确认历史计算 MVU → 冻结本次只读 MVU 上下文 → 既有宏/世界书/正则管线 → 受限 MVU 模板替换 → 最终请求与诊断。只读限定 MVU，不关闭正式请求既有的 M2 本地宏写入/保存行为。历史裁剪和摘要替代不能作为 MVU 回放输入。`stLocalVars` 保持自身命名空间，已有本地宏变量优先，未命中才读 MVU；MVU 读取不把 stat_data 全量写入 stLocalVars。预览使用独立副本，不保存、不触发变量/世界书事件。

摘要首批继续使用原始消息正文，沿用 M1 id/revision 来源验证，不新增“模板展开后总结”功能。因此人工变量覆盖不冒充正文 revision 变化；主聊天请求仍单独核对 MVU 来源链。未来若让摘要输入依赖模板/变量，必须同时扩展摘要请求及后续有效性检查，记录 MVU 上下文指纹，不能只改渲染。

### 3.4 显示与兼容报告

助手显示：原始正文 → 控制块识别及受限模板解释 → 原有选项 XML / Markdown / 状态栏优先级 → F17 白名单净化。变量插值使用转义文本，不让值变成脚本、事件属性或宿主 CSS。显示使用该消息的状态，提示词使用本次请求状态；两者参数显式区分。未知语法保留可查看原文与诊断，不能隐藏失败块后给出虚假成功状态。

文件导入、公库详情和消息诊断共用报告数据。报告注明初值来源、识别到的操作、支持/不支持模板、脚本依赖、外部资源与本方案差异。报告关闭不等于许可运行：主站文件导入报告本身也是提示，不是授权。

## 4. F19：逐层运行与宿主接口

### 4.1 层级与 HTTP 使用

| 层级 | 实际目标 | 资源 / 部署条件 | 拟实现策略 |
| --- | --- | --- | --- |
| 静态 | 保持现有 F17；F18 声明式显示 | 当前站点即可 | 默认路径，不运行 JavaScript |
| L0 | 卡片自身内联 DOM 交互 | 本页 opaque-origin srcdoc iframe | 用户确认后运行；CSS/DOM 只作用于 iframe |
| L1 | L0 + 固定兼容库和宿主 ABI 子集 | 同站点发布的审核后依赖 | lodash/jQuery 正式发行源锁定；缺库真实失败 |
| L2 | L1 + 固定第三方脚本/模块闭包 | 浏览器可下载、通过 CORS 的 HTTP/HTTPS 资源，或已有本机缓存 | 固定原始字节与 SHA-256；运行期无网络 |
| L3 | L2 + 经授权的出站请求 | 不同 origin 的 broker，可用 HTTP、本机不同端口或 HTTPS | 卡片仍 opaque-origin；broker 不持有宿主凭据 |

L0 不是静态层，主站也允许它执行内联脚本；不得把 F17 更名 L0 就交付。分站不采用主站部分正则小组件的自动 L0 执行，所有卡片 JavaScript 都有用户明确运行许可。

不要求新域名：L0–L2 无 broker；L3 不同端口就能形成不同 origin，例如宿主 `http://localhost:8765` 与 broker `http://localhost:8766`。生产也可以采用用户可用的不同 HTTP/HTTPS 来源。L3 保留“不同 origin”是架构隔离条件，不是 HTTPS 限制；若没有 broker，其他层仍可使用。

HTTPS 宿主加载 HTTP iframe、脚本或请求时可能被浏览器混合内容规则拦截；CORS、私有网络访问及 WebView 策略也由浏览器决定。实现按实际错误提示，不新增“仅允许 HTTPS”的应用校验、不伪装成功或静默更换地址。[MDN mixed content](https://developer.mozilla.org/en-US/docs/Web/Security/Mixed_content)

HTTP 下也保留完整 SHA-256：有 SubtleCrypto 时使用原生 digest，无该能力时使用经过测试、锁定版本的本机 SHA-256 实现；不能用 M1 快速指纹替代。随机实例令牌使用 `crypto.getRandomValues`，不依赖 randomUUID；getRandomValues 可用于非安全上下文。能力检测针对实际 API，不以页面协议一刀切拒绝。内容摘要用于识别所确认字节，不证明下载来源可信。[MDN digest](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/digest)，[MDN getRandomValues](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues)

### 4.2 运行文档与授权

L0–L2 `sandbox="allow-scripts"`，不添加 same-origin、弹窗、顶层导航、下载或表单权限。卡片代码只在 iframe 执行，不进入宿主 eval/Function 或 DOM；DOM 兼容库在 iframe 内正常操作自身界面。默认 CSP 禁止连接、对象、子 frame、Worker 及自动外部资源，分别限制 img/font/style/media；L2 仅按需要增加固定 Blob 模块来源。导航和外链另外处理，不能把 connect-src 当作全部资源限制。[HTML Standard](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox)

L3 外层 broker 使用不同 origin，内层卡片 iframe 同样 opaque-origin；外层可以有 allow-same-origin 以维持自己的协议来源，不能加载宿主同源卡片执行页。broker 配置明确允许的父页面 origin（包含实际 HTTP/HTTPS 地址与端口）。主站现有 config 白名单没有分站 Sites 来源，不能直接填主站 broker URL 当作可用功能；需部署自己的 broker 或获得其配置支持。

首批授权表只放页面内存，参考主站行为；刷新后重新确认，不先建立永久权限数据库。记录卡片稳定身份、HTML/脚本/依赖完整摘要、分站 ABI 版本、能力和网络策略；同步/恢复永不产生许可。固定依赖缓存为单独本机缓存，可持久保存但不等于授权，不上传云端。已有 `cardRuntime*` 顶层设置边界继续有效，不读取卡片同名元数据当许可。

授权后执行字节必须与报告/摘要一致。源码、依赖、权限或 ABI 改变时失效；同名卡不能共享许可。切换会话、删除消息、换选中版本、重建 iframe、撤销许可时关闭通道、释放 Blob/订阅/写入占用，再移除实例。已可靠提交的变量变更不因撤销倒退；未提交候选或迟到请求不能再提交。

L2 先明确用户同意下载所列依赖，再下载、流式限制字节、校验/展示 URL 与摘要，确认固定内容后运行。支持静态 import 和字面量动态 import；表达式动态 import、裸模块名、未解析远程 HTML 依赖明确诊断。闭包上限以主站基线 48 模块、单模块 3 MiB、总 8 MiB、32 卡脚本/总 8 MiB 开始；拒绝静默截断后假称完整卡片可用。下载 credentials omit、拒绝重定向、不发送 referrer；协议允许 HTTP/HTTPS。失败保持静态，由用户显式选择可用较低层，不自动授权降级执行。

主站 L1/L2 声明的 lodash 4.17.21、jQuery 3.7.1、Vue 3.5.13、js-yaml 4.1.0 是本次源码参考版本，不是分站已选定的依赖版本。实施时从官方发行源核对许可、兼容及当前安全修复后固定版本/字节/摘要，不从主站 vendor 路径直接复制库。

### 4.3 宿主 ABI 与数据权限

兼容全局对象在 iframe bootstrap 中提供：`OpenTavernFrontend`、`Mvu`/`MVU`、`TavernHelper` 和明确支持的 `SillyTavern.getContext` 等别名。分站使用自身 ABI 版本，不凭借主站 ABI 字符串宣称全部兼容。宿主按显式方法表 dispatch；未知方法返回 `UNSUPPORTED_METHOD`。

| 能力 / 方法 | 首批效果 | 提交 / 权限边界 |
| --- | --- | --- |
| 当前消息 / getCurrentMessageId | 绑定的稳定消息 ID；必要时提供派生 mesid 兼容索引 | 索引不作为写入身份 |
| chat.read / getChatMessages、getLastMessageId | 当前绑定会话的有界消息副本，最多 200 条 | 单独勾选；无系统提示词、CoT、其他会话、settings 或密钥 |
| character.read、theme.read | 当前角色所需字段副本、主题 token | 明确字段白名单，禁宿主引用 |
| variables.read / getVariables、Mvu.getMvuData | F18 对应消息状态副本 | 不暴露可变 live 对象 |
| variables.write.current / replaceMvuData、patchMvuData、replaceVariables、updateVariablesWith | 只修改当前绑定助手消息的人工覆盖 | 单写者、版本/来源链校验、F18 限额及可靠保存；ACK 后成功 |
| macros.substitute、display.format | 只读宏解释与 F17 格式化结果 | 预览不触发保存；不把代码送回宿主执行 |
| events.subscribe / eventOn、eventOnce | 本实例权限内的会话及 MVU 事件 | 完成确认后发布；关闭解除订阅 |
| events.emit.local | 实例局部自定义事件 | 不伪造宿主消息/保存事件 |
| display.refresh / refreshOneMessage | 重新显示绑定消息 | 不换消息内容、版本或读取其他会话 |
| input.write / setInputText、appendInputText | 回填当前绑定且仍活跃会话的输入框 | 尊重 F14 输入编辑序号及取消规则；不默认发送 |
| generate.trigger | 单独确认的发送/生成入口 | 复用既有生成保护；不开通任意 slash/宿主方法调用 |
| media.remote / runtime.networked | 明确资源或 L3 出站目标 | 默认关闭；不等同聊天/变量许可 |

`updateVariablesWith` 的函数若被支持，只在 iframe 对变量副本计算，提交结果带基线，宿主不执行传来的函数。不能把 `saveChat()` 或 `createChatMessages()` 做成成功空函数：主站部分实现有此兼容捷径，分站只提供真实效果；尚未实现的方法明确报不支持。只支持白名单 slash 操作，不给任意命令执行器。

握手校验 iframe 窗口引用、实例随机 token 与结构，随后交付专用 MessagePort。每次 RPC 核验实例仍在、会话/消息/选中版本、许可摘要、唯一请求 ID、方法、大小和频率。opaque origin 的 `null` 不能作为身份凭证；L3 外层另验精确 broker origin。目标已删除时直接拒绝，不能采用主站 getFrontendRpcContext 中回退当前活跃会话的逻辑。

写入 RPC 流程为：读取已确认基线 → 验证授权/消息版本 → 构建人工覆盖候选并回放 → persistConversationMutation 前后检查 → 合并成功 → 返回结果及事件。并发写入互斥只覆盖目标消息/版本；跨会话串用、过期基线、撤销后排队请求、保存完成前换版本都返回失败，不覆盖新内容。

### 4.4 可选联网层

L3 网络由 broker 代理，卡片 fetch/XHR 不直接使用宿主凭据。目标 origin 从实际执行材料提取作提示，再由用户选择；检测到 URL 不等于许可。允许 HTTP 和 HTTPS；精确 scheme/host/port 绑定，方法白名单、credentials omit、无授权/Cookie/Host/Origin 等敏感头转发、拒绝重定向、请求/响应流量配额。访问本机目标必须在所选目标中显式出现，不默认扫描或开放局域网。浏览器 CORS/私有网络限制失败就报告实际错误，不借宿主同步 API 绕过。

基线配额参考主站：每实例 50 请求、请求体 256 KiB、单响应 1 MiB、总响应 8 MiB、12 秒、最多 16 个出站 origin。按实际流式字节计数；超时覆盖响应体完整读取，撤销同时中止 fetch 与 body reader。主站 runtime.js 144–151 在收到响应头后就清理超时/活动请求，分站不照搬该生命周期。审计仅保存方法、origin、路径、字节和结果，不保存查询参数、正文或凭据。

broker 独立目录/发布产物，不混入 `functions/api/sync.js`、卡片代理或现有 Sites Worker 路由。新增远端服务的实际部署仍须明确目标与用户批准；这不影响 F18/L0–L2 的基础开发，也不再要求部署为 HTTPS。

### 4.5 移动端与资源限制

主站源码明确禁用 Android/原生壳 L3，不等于证明所有移动浏览器都限制 L2。分站先验收桌面与 Android L0–L2；L3 根据实际平台验证结果开放，未验收平台给出可用层级和失败原因，不因页面是 HTTP 自动禁用。

iframe sandbox 不提供硬 CPU/内存配额。DOM 卡片不能简单移入 Worker 而保持 jQuery/Vue/HTML 行为；本方案取消旧版“首批只能 Worker 计算 + 受信 schema 显示”的过窄兼容范围。可终止 Worker 用于独立计算时按需采用，不增加无用层。DOM 实例的关闭、失联、无限循环和内存压力必须在目标浏览器实测；若该平台无法恢复宿主交互，不把定时器称作可靠终止措施，也不在该平台交付执行能力。此处是验收风险，不是推迟写方案的借口。

## 5. UI 接入

不重做设置页面。沿用现有 theme token、light/dark/跟随系统、8pt 间距及 [openFeatureDialog](../src/app/core/60-feature-dialog-ui.js)：
