## 设置弹窗

设置弹窗用于集中配置连接、对话、记忆、扩展、界面与本地数据。普通表单在打开时建立独立草稿，关闭、遮罩与 Esc 等同完成；另有“放弃修改”入口。聊天推理统一使用远程 OpenAI 兼容 API。

### 信息架构

| 顶部标签 | 设置内容 |
| --- | --- |
| 连接 | 主 API、模型发现与手填 Model ID |
| 对话 | 上下文和采样参数、多套用户设定、系统与历史后提示词、两阶段生成、CoT、SillyTavern 预设 |
| 记忆 | 自动总结、触发阈值、总结提示词与总结 API、世界书预算 |
| 扩展 | Packy GPT Image 与云同步 |
| 界面与数据 | 存储状态和分项恢复、主题、阅读宽度/字号、聊天背景、启动恢复、消息显示、提交与串流行为、效能模式与新手引导重放 |

### 交互要求

- 打开设置时默认显示“连接”，同一时间只显示一个设置面板。
- 点击标签切换面板；键盘可用左右方向键、Home 和 End 在标签间切换。
- 标题与标签栏固定在弹窗顶部，当前面板独立滚动；切换标签后从新面板顶部开始。
- 桌面端所有标签保持为一行；移动端同样保持单行，并允许标签栏横向滚动。
- 标签和面板使用 `tablist`、`tab`、`tabpanel` 语义及对应的 ARIA 状态。
- 标签文案支持简体中文、繁体中文和英文。
- “连接并获取模型”和“刷新列表”读取当前草稿连接的 OpenAI `/models` 或 Ollama 兼容列表；选择列表项写入草稿 Model ID，列表外的手填值不得被刷新覆盖。关闭、放弃或恢复替换设置后的迟到结果不得写入新表单或已提交设置。
- 不提供 Ollama 手动开关；端点包含 `ollama` 或使用默认 `11434` 端口时自动合并或降级重复的 system 消息。
- 频率惩罚和存在惩罚范围均为 `-2..2`，必须作为 `frequency_penalty` / `presence_penalty` 写入聊天请求。
- 用户设定支持新建、复制、删除和切换；每套包含设定名称、`{{user}}` 名称和人设描述，每个对话保存自己的 `userPersonaId`。
- 完成前校验数值、范围及选项，非法值阻止关闭并定位错误；只提交本次改变的普通表单字段。外部恢复替换设置对象、同一字段被另一操作改变时拒绝旧草稿覆盖，用户可放弃后重新打开。
- 放弃不保存、不上传，并恢复主题与背景预览。预设/正则 CRUD、用户设定切换及数据操作即时保存，不能由放弃旧表单撤销；用户设定正文提交绑定打开时的设定 ID。云同步按钮只即时提交当前连接配置，不提交其他未完成表单。页脚说明上述边界。

### 界面与生成行为

- “显示回复头像”默认关闭；开启后助手消息和流式气泡在名称左侧显示对应角色图片，无图片时显示名称首字。群聊按消息 `speaker` 解析，已移出群聊的历史发言者仍可从角色库取图。
- “显示消息 Token 统计”默认关闭；开启后在助手气泡下显示输入、输出 Token 与生成速度。API 返回的 `usage` 无论开关状态都写入对应助手消息；旧消息缺少 `usage` 时不显示也不补写。
- “需要 Cmd+Enter 来提交”默认开启：Cmd/Ctrl+Enter 提交、Enter 换行。关闭后 Enter 提交、Shift+Enter 换行；输入法组合态不得误发送。
- “启用串流”默认开启。开启时发送 `stream: true` 并请求流末尾 usage；关闭时发送 `stream: false`，等待 JSON 完整响应后一次显示。主回复、重生成和二阶段生成共用此设置。
- SSE 与 JSON 共用完成信息 `{interrupted, finishReason, completionReason}`，并绑定发起请求时捕获的 controller。SSE 按任意字节块和 CRLF/LF 行边界解析，只跳过无法解析的单条 `data`；JSON 缺少 `finish_reason` 的既有响应仍按正常完成处理，usage 只读取标准响应根级 `usage`。`finish_reason: stop` 或 SSE `[DONE]` 可正常结束；`length`、`content_filter` 及其他未知 `finish_reason` 均保留原始原因并按未完成处理，不得伪造为 `stop`。EOF 有 `finish_reason: stop` 时正常结束，没有任何终止依据的 EOF 仍为中断；abort 与流式空闲超时分别记录 `completionReason: abort` / `timeout`。reader.read 抛出 AbortError 时即使 signal 尚未标记 aborted 也必须按中断处理。
- SSE `[DONE]` 是立即终止边界：同一网络 chunk 中其后的帧以及后续 chunk 全部忽略，完整 UTF-8 字节在同块或跨块送达必须得到相同结果。DONE 前保留已解析的 `finish_reason` 与 usage；DONE 前的供应商 `error` 帧以及 2xx JSON 错误对象仍进入既有错误分支并保留供应商消息。错误分支不提交错误帧前的部分正文；重生成继续保留原完整回复。中断、截断或过滤但已有正文时沿用部分回复契约：普通生成保存未完成部分，重生成只追加 `interrupted` 候选版本且不替换原有效版本。
- 业务回调异常不得被 JSON 解析容错吞掉；解析器只忽略单条畸形 JSON。onComplete 同步抛错或返回 reject Promise 时，终止回调仍只尝试一次，异常由解析器/请求入口返回的 Promise 交给调用者，不再重派为 onError；未终止的 onToken 同步异常仍只调用 onError 一次。旧响应结束只释放自己的生成 controller，不得清除较新操作的生成、停止或提示词构建状态，也不得用旧 controller 重置新请求的空闲超时。
- T02 独立回归使用原 HEAD 响应解析源码与完整 UTF-8 字节夹具复核：`[DONE]` 在同 chunk 和跨 chunk 均正常结束，DONE 后帧均被忽略；原缺陷是 DONE 前供应商错误被忽略和完成原因缺失，不是 DONE 被误判为中断。初版 T02 候选引入的 DONE 后分块依赖在独立审查中被拒绝并已修正；夹具自身截尾不计为生产缺陷。协调者完整检查（66 项 Python）、独立异常/恢复观察器及两套 Chrome 回归通过，含错误/截断保留、JSON/SSE 一致、EOF/中止 Promise 转接、错误后不再送出文字和正常发送/自动总结，尚未发布。
- T08 生成传输迁移将 HTTP、SSE/JSON 解析和单次结算封装到 `createGenerationTransport` 闭包；factory 显式接收 fetch、时钟、状态控制器、设置快照和解析 helper，不读取活动会话，也不操作 DOM、存储、回复版本或保存队列。`streamChatWithMessages` 与 `streamChatCompletionResponse` / `readChatCompletionResponse` 保留旧名称和旧参数作为薄适配，仍向主回复、二阶段、一次格式纠正和重生成/续写报告原有增量、完成、错误及 usage/思考/完成原因。传输层只结算请求；可靠保存继续由原 `finishAssistantMessage`、`commitResponseVersion` 和 `persistConversationMutation` 入口完成，未建立第二套保存路径。该拆分及两模块组合源码已通过协调者构建、完整检查和真实浏览器验收，未发布。
- T09 重复符号处理：公共角色卡搜索只使用共享 `escapeHtml`，消息和库搜索统一转义 `& < > " '`；会话导入回退入口 `registerImportedConversationCharacterPreservingExisting` 保留同 ID 已有完整元数据并忽略空输入，角色导入入口 `registerCharacterImportReplacingExisting` 按原有角色导入策略克隆并替换同 ID 卡片，也忽略空输入。两个入口不再共享隐式全局函数名。
- 上述角色替换 helper 是保留的回退代码；当前完整应用的常规会话导入优先调用 `migrateCharactersToRegistry`，原本就保留已有资料。本次实际 Chrome 对照确认该行为不变，不将重名风险描述成已复现的常规数据覆盖。
- T09 `scripts/check-app-contracts.mjs` 以 TypeScript AST 检查 classic 顶层跨分片重复函数/变量、独立模块局部作用域隔离、manifest 重复/缺失/顺序，以及 T07 `createMessageDisplayModel` 返回 `prepare`/`prepareOptions`、T08 `createGenerationTransport` 返回 `request`/`readStream`/`readJson`/`buildCompletion` 的注入依赖和调用接线。静态检查不执行用户卡片代码，也不宣称覆盖所有动态全局调用。`npm run check:app-contracts` 已接入完整 check，app 构建在写产物前执行；契约失败不会部分覆盖 bundle。
- T10 发布检查入口 `npm run check:release` 必须真实执行 Sites 构建、完整源码检查、部署资源检查和六组 Chrome 回归；缺依赖、端口冲突、测试/截图/系统主题证据缺失、源码或资源漂移均失败。报告保存 SHA、完整资产哈希、命令退出码和各组独立截图；预览与 dist/client 字节一致才通过本地门禁。真实供应商验证独立记录，模拟成功不代表真实模型成功；工具不执行发布。
- “流式文字动画”默认关闭，只动画新到达的增量，不重播已有文字；支持淡入、上移、侧入、缩放和下落，支持 Token 批次或逐字符。效能模式或系统“减少动态效果”生效时自动停用。
- “流式空闲超时”默认关闭；启用范围为 15–300 秒。超过设定时间没有收到新正文或思考内容时中止请求；普通生成在已有增量可用时保存部分回复，重生成按下文版本保护规则处理；仅有 SSE 保活数据不得重置计时。
- 默认二阶段选项须兼容模型附加的 Markdown 代码围栏、前后说明文字及缺失最外层 `</options>` 的输出；保存前统一规范为标准 `<options>` XML。主回复中的 fenced/inline 代码示例、转义 XML、说明中的字面标签和跨代码保护区或没有完整 option 的无法确认控制块保留原文，不得被保存、历史请求或显示清理截尾；没有任何完整选项时按失败处理，不得保存错误格式正文；自定义二阶段提示词仍保留状态栏等非选项格式。
- 默认二阶段提示词（等于 `DEFAULT_TWO_STAGE_PROMPT`）须在正文/最近上下文后追加明确的 user 选项请求，要求只依据本轮正文生成一个 `<options>` 内的 2-4 个 `<option>`（title/description），不得续写正文或 dream 包装；两种最近上下文路径都追加，自定义提示词不追加默认选项专用指令。默认返回有文本但没有完整有效选项时，最多追加一次基于原上下文与明确格式指令的 API 格式纠正请求（因此可能额外发起一次请求），不把无效回复保存为第二阶段，也不用本地杜撰选项；空响应、中断、`length`、`content_filter`、未知截断、网络或保存失败、自定义提示词均不重试，截断不得伪装成格式失败触发纠正，完成原因在失败提示中保留。第二次仍无效按原失败保护处理，原正文与旧选项不变，`onDone` 只结束一次。纠正前须重新核验目标会话与来源修订，来源变化后不再请求，并按原二阶段失败保护提示用户（同一失败分支、不新增第二套处理），保留原有正文/旧选项；纠正请求复用清单保证已定义的 `buildSecondStageCorrectionMessages`（无 typeof 回退，避免静默丢失格式指令）。请求预算与供应商采样参数沿用现有值。
- 重生成与续写的主阶段、候选二阶段和最多一次格式纠正绑定同一次 operation 与 settings 快照；二阶段预算只取同次 `maxTokens` 与 1024 的较小值，下一次操作才读取 live 新设置。请求上下文前缀副本拥有自己的可写宏候选状态，原会话的 target/prefix/MVU/修改条件仍独立校验；候选未成功写入前不得作为新增主消息重绑定，真实 `commitResponseVersion` 成功替换后才按实际提交结果清理或绑定来源。
- 旧操作迟到完成、错误或停止不得保存失效候选，也不得清除较新操作的 controller、空闲计时器、生成状态或气泡；目标删除、替换或来源修改仍走原失败保护。生成 runtime 身份只存在运行时或不可枚举元数据，不进入消息 JSON、备份、云同步、API payload、诊断 settings 或 key。
- 重新生成二阶段选项时，旧选项须保留到新结果通过格式校验并成功保存后再原位替换；格式错误、空响应或网络失败均不得删除上一次有效选项。
- 二阶段生成期间切换会话时，结果须保存到发起请求的原会话，流式内容不得出现在切换后的会话中。
- 卡片库和聊天页顶部所示的语言/GitHub 控件组只保留“立即同步”；语言能力及首次引导内的语言选择不因此删除。

### 总结与记忆行为

- 自动总结只能在尚未覆盖的普通消息数量达到用户设置的触发阈值时启动；阈值只决定何时触发，触发后继续保留最近消息缓冲。
- 新摘要使用 `summaryVersion: 2` 和 `sourceMessages: [{id, revision}]` 记录生成时来源；`coveredStart/coveredEnd` 保留供范围展示及旧格式兼容，不再单独证明有效覆盖。
- 摘要每次使用时根据当前消息重新核验来源存在、顺序、内容修订与范围完整性；来源匹配为 `valid`，来源记录不匹配为 `invalid`，没有 v2 来源记录为 `unverified`。只有 `valid` 摘要参与模型上下文注入和原文覆盖。
- 自动总结与上下文计数必须按已核验来源在当前消息中的有效区间并集计算未覆盖消息；局部总结、重叠总结或越界旧记录不得把区间外消息误判为已覆盖。
- 聊天页上下文进度只显示尚未被总结覆盖的普通聊天消息数，并与自动总结触发计数一致；SillyTavern 预设、世界书、二阶段消息和空正文不得计入该进度。
- 手动“最近 N 轮”和自定义范围总结只覆盖已核验的实际来源区间，不得按最大 `coveredEnd` 删除范围外的更早消息。
- 只有数字区间的旧摘要保留文本与原区间，标为 `unverified`；不注入模型上下文、不隐藏原文、不用升级时当前修订伪造生成时来源。列表提示建议重新总结；本批不提供将旧摘要直接改为可信的确认入口。
- 编辑、删除或切换来源回复版本后立即重新校验摘要；`invalid` 或 `unverified` 只影响模型使用，不能删除摘要文本或原始聊天。原文仍受原有最大上下文窗口限制，不保证所有历史同时发送。
- 同一会话任一时刻只允许一个总结请求；重复的自动或手动触发不得产生第二个 API 请求或重复总结记录，请求结束或失败后必须释放状态。
- 请求冻结发起会话、来源 ID/修订及输入副本；返回时必须核验仍为原存活会话与原来源。请求期间编辑、删除或云恢复替换目标时拒绝迟到结果，不写入其他会话或重新创建已删除会话。
- 新摘要须先作为待提交候选，等待立即本地写入完成确认后才加入有效覆盖、模型注入或报告完成；模型返回成功、安排写队列或展示候选均不等于可靠保存。请求失败、空结果或保存失败不推进有效覆盖；保存失败移除本次新增候选，并修正写入期间捕获的后续待写快照，不把失败摘要安排为自动上传。
- 总结 API 的非 2xx 响应必须显示 HTTP 状态及供应商返回的错误信息；成功响应不是合法 JSON 时必须明确报告格式错误，不得统一伪装成 `Unexpected API response`。
- 缺少 `summaries` 字段的旧会话在首次成功总结时必须自动初始化总结列表，不得因旧数据结构导致结果无法写入。
- 自动总结失败时必须向用户显示具体原因，不能静默失败；失败后不得按成功状态刷新上下文计数。
- `npm run check` 必须覆盖部分范围裁剪、重叠区间后的自动触发、上下文计数、阈值边界、并发防重、锁释放和 HTTP 错误透传。

### 回复版本与可靠提交（M1）

- 用户、助手和二阶段消息均有稳定 `id` 与内容 `revision`。缺失或重复 ID 的旧消息按会话 ID、原位置与内容修订确定性生成 `legacy-` 身份；已有合法唯一 ID 保留，重复执行规范化不改变结果，同一旧快照可得到相同身份。不同旧快照不按下标强行合并为同一消息。
- `revision` 是角色、正文、思考、发言人、阶段、主回复关联及附件等内容的 `m1:` 指纹与长度，不是计数加一，也不是安全哈希或权限证明。编辑时 ID 不变，相关内容变化后重算修订。
- 重复 ID 涉及的摘要来源标记为歧义，不能成为有效覆盖；二阶段关联按原消息位置修正。新增二阶段消息保存 `parentId` 和对应主回复的 `parentRevision`。
- 主回复重生成目前只支持最近且前一条普通消息为用户消息的主回复；中间历史回复直接提示不支持，原数据不动。请求逻辑排除目标，候选在独立流式区域显示，不先删旧正文或关联二阶段。
- 请求绑定发起会话、目标对象、目标修订及前置消息来源。返回时会话或来源变化则拒绝替换；切换界面不改变写入目标，也不在其他会话显示该候选。
- 待提交回复以独立候选组准备：立即写入完成确认前，原正文、选中版本和关联二阶段仍为有效组；确认成功且目标仍匹配后才整组切换正文。不能先让候选成为当前有效正文，再用最终保存失败回滚掩盖未落盘窗口。
- 写入前和完成确认后均核验发起会话与目标。保存期间云恢复替换对象、删除会话或改变来源时拒绝迟到候选；失败补偿不能用请求前的会话副本覆盖新云数据、写入其他会话或复活已删除会话。
- 回复版本记录版本 ID、创建时间、主回复完整消息副本和关联二阶段消息组，保留正文、思考、usage、发言人和未知扩展；主回复用 `responseVersions` / `selectedResponseVersionId` 保存版本列表及选择。成功后整组选择新版本，旧主回复和旧选项仍能切回，不自动裁剪历史版本。
- 网络错误、供应商错误帧、空正文、二阶段格式错误或本地保存失败保留原有效回复及选项。主回复因 EOF 无终止依据、abort、空闲超时、`length`、`content_filter` 或未知完成原因而中断但有可用正文时，仅追加带 `interrupted` 标记的不完整候选版本并在提示中保留原因，原有效版本继续选中；版本入口明确标注不完整，不静默替换旧正文。
- 二阶段独立重生成亦使用整组版本提交；默认选项格式规范化规则不变，自定义状态栏等非选项结果继续保留。失败或中断不删除原二阶段结果。
- 切换版本重新校验摘要且不删除后续消息；编辑已经存在版本历史的主回复或关联二阶段结果时新增版本，不覆盖原版本快照。主正文改变后清除当前组已不再对应的旧二阶段内容，旧版本中的二阶段仍可恢复。
- 摘要新增、重生成结果与版本切换使用现有串行持久化队列的立即写入及错误传播。提交期间保护目标会话；保存失败在队列释放前回滚本次变更，并修正后续待写快照。拒绝空快照同样按失败处理，不能把安排延迟写入视为已经落盘。
- 迟到候选的持久化补偿只在此前持久层记录与本次被拒绝候选快照精确匹配时，才允许针对已删除目标纠正空状态；不能以此覆盖新的云恢复内容或放宽正常启动的防空快照护栏。此边界需用实际存储服务与模拟故障分别验收。
- 上述纠正空状态取得可靠保存确认后才写入既有 clear marker；自动选择快照时排除早于 marker 的旧副本，避免空状态被旧数据复活。后续正常保存或显式恢复旧备份，仅将物理快照 `lastSaved` 提升到至少 `marker + 1`，不改变正文或会话逻辑 `updated`；保留 marker，也不删除旧备份。护栏及标记写入失败、排队快照、旧备份恢复用例已通过。

## SillyTavern 卡片运行时兼容

### 宏

- 系统提示词、预设、世界书和历史消息在发送模型前支持常用 SillyTavern 宏，包括角色/用户/用户设定、最近消息、换行、预设提示词以及 `getvar` / `setvar` / `addvar` / `incvar` / `decvar`。
- `random` / `pick` 在同一会话和相同调用顺序下保持确定性，避免重新查看提示词时无故漂移。
- 会话变量保存于会话自身；未知宏原样保留，避免破坏将来版本的卡片文本。
- 宏解析限制输入长度、递归层级和执行步数，防止异常卡片阻塞页面。

### 声明式正则

- 支持角色卡及 SillyTavern 预设的 `regex_scripts`，按显示、用户输入、模型输出、世界书和思考内容等 placement 工作。
- 支持显示/提示词阶段、最小/最大深度、捕获组替换、`trimStrings` 与编辑消息约束。
- 角色卡正则默认关闭，首次导入时必须分别取得授权；角色编辑器可独立控制显示文本和模型提示词权限。
- 预设正则导入后默认关闭，首次导入明确询问，设置页可随时切换；导出时写回 `extensions.regex_scripts`。
- 只允许有长度上限的 `RegExp` 文本替换，绝不执行角色卡或预设携带的 JavaScript。
- 正则执行使用单一可终止 Worker 串行队列：提示词任务优先于显示任务，提示词请求不因显示积压被拒绝；同一替换 key 的显示任务在提示词请求到达时复用并提升优先级，跨阶段共享，取消显示链不得破坏提示词仍需要的任务。
- 显示队列准入上限 256，超出者进入等待队列；等待与待执行显示任务都绑定到当前有效的消息/显示链，新版本文本取代过时 pending、关闭规则/删除消息/切换会话时立即释放等待任务，因此等待队列实际有界，不会随流式刷新或 500000 字符原文逐版本积累；显示容量只影响显示链的准入边界，300 条可见消息仍会全部收敛完成。
- 进行中的任务按替换 key 独立去重，不因完成结果缓存（上限 256）淘汰而重复执行或重复入队；失败结果不缓存，Worker 错误与 500ms 超时后可重试。
- Worker 的下载/初始化与正则执行分开计时：主线程构造 Worker 后先提交 `regex-worker-prepare` 握手请求，Worker 只对该请求回 ready，主线程收到 ready 才提交真正任务并启动 500ms 执行计时，因此装载延迟不计入执行超时；未收到 prepare 时脚本不主动发送 ready，旧标签页（第 11 版及以前）直接提交正则任务仍按原协议在第一条消息返回 result，新发布不会打断旧标签页。Worker URL 带固定版本参数避免部署平台长期缓存旧脚本。装载等待本身有 10 秒上限（`REGEX_WORKER_LOAD_TIMEOUT_MS`），超时明确报“加载失败”，不会无限挂起。Worker 用 `performance.now()` 返回实际执行耗时，正常返回但实际执行超过 500ms 同样拒绝；执行超时提示包含规则 `name`/`scriptName`，缺失时仍正常报错。完成、错误或超时都会清理计时器、终止 Worker 并释放队列，真实执行仍保留 500ms 终止隔离。
- 显示按消息保存当前串联链（流式等没有消息对象的路径按会话保存）：每条规则以上一条结果作为输入，显示积压全部完成后结果稳定、不重复重渲染、也不无限调度；生成期间的显示完成刷新合并并延后至生成结束，避免重建历史销毁流式气泡，等待项只受当前有效显示链数量约束。
- 显示链失效签名采用结构化 JSON，覆盖原文、规则顺序/开关/深度，以及替换参与展开的宏上下文（预设 main/jailbreak 正文、历史最近消息、会话变量、当前消息对应的 MVU 与世界书）；签名不包含 `random`/`pick` 的展开结果，避免每次渲染无限重算；显示替换沿用历史语义，附带当前消息与其对应 MVU。
- 提示词历史消息在格式化前保留内部来源消息、ID、修订和对应 MVU 快照；同步与异步正则替换共用同一上下文，当前模板使用当前数据，历史模板使用各自来源快照，不被宏环境的最新 `mvuData` 覆盖。最终只向供应商发送现行 `role/content`，不包含来源 ID、快照、权限或运行对象。
- 正则结果缓存键覆盖输入、规则、替换结果、来源 ID/修订、MVU 快照、阶段、深度和影响宏的设置摘要；编辑消息、更新 MVU 或切换回复版本后不得复用旧结果。冷缓存同步首调用仍允许返回原文，等待异步刷新完成后同步/异步结果一致；提示词优先、任务去重、失败不缓存、冷缓存异步刷新与取消保护保持不变。
- 关闭规则、删除消息或切换会话后过时链停止后续步骤并释放待执行任务，取消不产生未处理的 promise rejection；复杂规则在没有消息对象的显示路径（流式）仍由 Worker 执行，仅无 Worker 时才退回固定宽度同步替换；显示失败保持原文且不自动重试。
- Worker 启动与继续调度合并到单个微任务，让当前同步 DOM 渲染栈先返回，避免 300 条历史全量重绘阻塞 Worker 消息与 500ms 超时回调造成假超时；显示结果刷新按当前正则批次合并，仅在批次清空（pending 为空）后一次性重绘完整链结果，不因每条规则完成就重建整表。

## 构建与漂移门禁

- 备份现有 bundle 后运行 `scripts/build-app.js` 重建，以 SHA-256 内容哈希比对重建结果与现有 bundle。
- 一致时明确输出同步结论；不一致时恢复原 bundle 并以退出码 1 失败，输出双方哈希并提示运行 `npm run build`。
- 不得改变 `scripts/build-app.js` 的拼接逻辑。

验收：

- 当前仓库状态下漂移检查能得出明确的一致/不一致结论。
- 修改任一源分片且不重建时，检查失败并指明需要运行 `npm run build`。
