### 阶段 A 实施边界（2026-11-07）

- **03 连接档案**：`settings.connectionProfiles` 保存可移植描述（稳定 ID、名称、用途、协议、端点、模型、采样参数与可选提示词预设引用），`settings.activeConnectionProfileIds` 分别记录主回复、摘要和 Embedding 选择。主/摘要档案只投影到各自运行时字段，切换主档案不改变独立摘要选择。主档案的 `thinking` 与摘要档案的 `summaryThinking` 分别保留受支持对象或显式 `null`；未记录的字段不投影，显式 `null` 在切换时清除上一档案值。Embedding 档案本阶段只保存描述与选择，不建立索引、不发起 Embedding 请求。`saveApiKey=true` 时档案密钥写入独立本机存储 `opentavern_connection_profile_credentials`，按协议与端点配对；写入后回读校验，配额/写入失败会回滚内存凭据并在编辑器报可重试错误，不显示已保存；端点或协议变化后旧密钥不再匹配。`saveApiKey=false` 时只在内存使用，普通持久化与档案事务快照都不得写入密钥。旧配置密钥只在档案协议/端点与旧主连接或旧独立摘要端点配对时迁移，远端替换的新端点不会继承旧密钥。可移植过滤与备份恢复只白名单化连接档案并剔除其嵌套密钥，预设、角色等原始元数据保持原样。恢复同时选择普通设置与预设库时，导入档案 `parameters.presetId` 中属于本次导入的预设引用随预设冲突副本映射；未导入引用、仅设置及仅预设选择不改写，保存失败不应用映射。迁移只创建与当前实际配置等值的默认档案，不改变默认服务、模型、流式或提示词配置；缺失选择保留为空并提示，不静默切换。档案保存与选择使用候选、立即持久化和确认提交；生成中拒绝切换，设置草稿冲突、失败快照与迟到模型列表结果均被隔离。档案选择属于即时数据操作，设置中的“放弃”不会回退已提交的选择。
- **04 快捷回复**：`settings.quickReplyGroups` 保存可启停、可排序的按钮组与按钮，范围为全局、角色或会话；同一组按 ID 去重，会话可停用继承组。按钮默认插入输入框，非空草稿采用追加，显式“直接发送”才复用真实 `sendMessage` 的忙碌、可靠保存和错误流程；双击、生成中、保存中与切换会话不得重复发送。正文使用现有受支持宏，未知宏保持原样，不执行 JavaScript、shell 或新命令语言。导入的按钮一律重置为插入，导出不携带凭据；按钮组与绑定随普通设置备份/同步。备份恢复同时选择普通设置与会话时，会话范围且目标属于本次导入的按钮组随会话冲突副本改绑；仅设置、仅会话、全局/角色范围及未导入目标不改写。
- **09 群聊策略**：旧会话没有策略时继续使用原轮流规则；显式非法 mode 被拒绝，不静默归一。`conv.group.speakerStrategy` 保存手动、自然或概率策略、成员非负权重、手动下一位及自动轮次上限（1–10 步，间隔 1–30 秒）。`@` 优先，但静音成员不得暗中参与；全零权重、全静音或无手动选择时说明原因并停止。自动轮次只能由用户启动，一次成功保存的助手回复计一步；失败、切会话、修改成员、修改策略或页面恢复均终止，不隐式重放。取消自动轮次只禁止未来轮次，当前已发出的请求仍按正常可靠保存结算，之后不再排下一轮；普通停止按钮中止当前请求，中断完成仍释放状态。迟到或重复完成不得清除新请求的锁。自动轮次复用普通生成、二阶段、摘要、停止和可靠保存路径，不调用额外裁判模型。异步失败时若已有打开的二级 HTML 对话框，实际错误写入该窗口现有错误容器，不另开被 top layer 遮挡的玻璃提示；没有二级窗口时才使用原玻璃提示。失败路径释放生成锁、停止后续轮次且不保存助手回复。
- **10 分支图**：继续复用 `branchOf` 与稳定消息 ID，只读展示父链、同源分支和后续分叉；回复版本不作为独立会话节点。节点显示会话名、分叉处摘要和当前高亮；父会话缺失、分叉消息删除及循环引用均给出说明并停止展开。打开会话沿用当前最新消息定位；“查看分叉处”显式扩大历史窗口并定位目标，不被普通入页底部对齐覆盖。浏览不发送模型请求、不修改消息，也不新增合并、批量删除或剧情改写。备份恢复的导入子分支在父会话同时恢复时把 `branchOf.conversationId` 映射到恢复副本，`userMessageId` 与其他元数据保持；父会话未导入的引用保持原语义。
- **13 预设差异**：比较两套已存预设或导入候选的提示词块、顺序、启停、角色、位置/深度、采样参数、正则、元数据与缺失/空值差异。提示词和正则优先按稳定 ID 匹配，无稳定 ID 的旧格式按新增/删除展示，不按同名猜测；对象键顺序不产生伪差异，真实提示词顺序变化单独显示。长文本按行及词级渲染，全部作为安全文本写入 DOM，恶意 HTML 不执行。比较只读，不改变当前预设、草稿、生成连接或请求；导入候选保存继续走原预设可靠事务，不增加自动合并。

阶段 A 运行回归入口为 `npm run check:tavern-stage-a`，已接入 `npm run check`；隔离浏览器脚本为 `node scripts/test-tavern-stage-a-browser.mjs`（支持 `OPENTAVERN_TEST_URL`、`OPENTAVERN_TEST_OUTPUT` 或 `OPENTAVERN_OUTPUT`、`OPENTAVERN_PLAYWRIGHT_MODULE`），输出 `report.json` 与截图。浏览器脚本使用合成模型，覆盖 390/1280px 浅色、深色与跟随系统、管理界面、保存/刷新（启用恢复上次会话）、停止自动轮次/普通停止/切会话确认/错误、凭据写入失败、截图、横向溢出和 `pageerror`。失败模型场景在群聊配置窗口打开时断言实际错误可见、没有待确认玻璃框、生成锁释放、只发一次请求且不保存助手回复，随后通过真实关闭继续后续矩阵；关闭窗口后另验证玻璃提示路径可操作。主协调者最终构建、完整检查和整组实际 Chrome 复跑均通过，证据见开发验收记录。真实供应商、手机 Chrome 真机与部署结果仍未验证，单独记录，不以模拟通过代替。

### 阶段 B 实施边界（2026-11-08，本地验收通过）

- **共享检索基础**：`retrieval/` 是 01 与 02 共用的唯一检索业务模块，负责来源分块、稳定来源 ID/修订、OpenAI 兼容 Embedding HTTP 适配、有界可取消索引、相似度检索、去重/预算和本次实际注入来源。不复制第二套向量服务。索引与查询缓存保存在独立本机 IndexedDB `opentavern-retrieval-index`，不进入 canonical 快照、云同步、普通导出或调试载荷；清索引、重建或取消不删除消息、摘要或资料原文。向量元素只接受有限 `number`（拒绝 null、布尔、字符串、对象等强转值），配置维度必须是严格有效整数、不得向下取整；预先取消的外部 signal 在 fetch 前拒绝并解绑监听；索引库打开与事务使用身份/结算围栏，超时后关闭迟到连接、abort 并丢弃不确定事务，worker 返回 Promise 的拒绝立即观察，不产生未处理拒绝。
- **Embedding 连接**：只读取“连接”中用途为 Embedding 的明确选择及其本机配对凭据，不继承主回复或摘要密钥；Anthropic/DeepSeek 聊天端点不能直接当 Embedding 使用。端点支持原始 base、以 `/v1` 结尾或完整 `/v1/embeddings` 的明确规范化，认证只放在请求头，不写入 URL。服务签名由协议、规范化端点、模型和配置维度组成；实际维度再进入索引签名，模型、端点或维度变化不得复用旧索引。测试按钮由用户显式点击，发送一段固定测试文字并展示实际返回维度、请求次数和延迟；打开设置、预览、启动、恢复或读取资料不会发起 Embedding。
- **01 语义记忆**：默认关闭。启用后当前会话始终是来源，可额外显式关联其他会话；只索引已可靠保存的消息和有有效来源的摘要，不索引未完成草稿。来源引用会话、消息/摘要稳定 ID、消息修订、分支归属和摘要有效性；编辑、删除、切换回复版本或摘要失效后，旧片段立即不再满足当前来源，不必等待后台重建。发送边界可归并新增/变更的记忆；最近已注入历史、被有效摘要覆盖的消息及重复文本不重复注入。失败时退回现有摘要与历史并继续生成，不残留生成锁。资料与记忆片段仅是原文引用：来源名称、修订、片段正文均不经过普通角色/历史的 ST 宏、MVU 模板、正则或变量写入/读取，不能授予模型工具或宿变量权限；普通角色、预设、世界书和历史宏保持原行为。
- **02 资料库**：新增独立 `state.documents` 实体，保存 UTF-8 TXT/Markdown 原文、名称、格式、内容摘要修订及全局/角色/会话显式绑定。默认不跨未绑定资料检索；同名资料不覆盖，替换先生成候选并可靠保存成功后才切换，失败保留原件、旧绑定和可重试候选；删除或替换立即使旧召回失效。失败候选保留其保存时的资料库基线；若期间已有并发成功修改，重试以冲突拒绝并保留可导出草稿，不把整库旧候选覆盖当前资料。资料文本只作为资料显示，不作为宿主指令、语法或脚本执行。资料列表“导出”生成真实 UTF-8 TXT/Markdown 原文，扩展名与 MIME 随格式，可原样重新导入并生成同名副本；结构化资料与绑定仍由完整/分项备份负责。名称可在资料库二级表单中重命名，空白或超过 180 字显示校验错误；重命名不改变正文修订或向量，导出文件名随名称更新，重名沿用现有副本策略。原文与名称随完整备份与云同步保存，向量仍只在本机重建。
- **生成集成与界面**：检索在 `buildMessagesForAPIAsync` 捕获的会话、消息修订、连接和设置范围内执行；注入位置固定在摘要之后、普通历史之前，分别显示“资料/记忆”来源、名称、修订和片段，并受记忆与资料各自的估算 Token 预算及总片段数限制。检索消息带原文引用边界标记，跳过正则、宏、MVU 模板、outlet 解析和 `replacePlaceholders`，正文与来源元数据按索引时的原文进入实际请求和下一次预览；实际请求来源诊断一致。检索返回后继续按捕获的设置、Embedding 服务签名、授权来源范围、来源修订与绑定复核，并在后续异步格式化/宏处理结束和实际模型发送前再次校验；配置、连接、绑定或来源变化时丢弃本轮结果、零聊天请求、释放生成锁并保留原消息。实际请求诊断记录本次来源、模型、维度和请求批次数，“最近实际请求”可查看这些来源；“下一次预览”只使用本地已缓存的查询向量/索引，缓存不存在时明确显示未检索，不发出隐藏 Embedding。停止、切会话、换连接、切角色或来源变化后，迟到检索结果不得注入或写入。
- **设置交互**：检索开关、预算与最低相似度接入既有设置草稿合同：编辑只改草稿，点击“放弃”不保存，点击“完成”后统一持久化；change 事件不再暗中提交。索引、连接测试与资料 CRUD 是明确的即时数据操作，读取已提交配置；未完成的检索设置需先点击“完成”才用于索引或测试。检索字段不再单独吞掉持久化失败，完成后沿用全局设置保存的既有失败边界。

- **隔离执行**：`src/app/plugins/40-plugin-isolation.js` 生成只含受信引导和随机 nonce 的 srcdoc iframe，iframe 使用 `sandbox="allow-scripts"`、无 same-origin；CSP 固定 `default-src 'none'`、`script-src 'nonce-…' blob:`、`worker-src blob:`、`connect-src 'none'`，其他资源全部拒绝。插件入口不拼进 srcdoc 或宿主 DOM，而是通过受检 MessageChannel 传到 iframe，再由 iframe 用 Blob 组装“受信 SDK + 插件 entry”到 DedicatedWorker；Worker 无宿主 DOM、窗口、设置或 API 密钥，opaque origin 的存储不共享宿主命名空间。SDK 提供有界 `ready/fail`、事件订阅、当前会话统计、私有存储、受控 UI 和网络 RPC，并跟踪/终止插件创建的嵌套 Worker；宿主经端口发送的 `plugin-host-rpc-result`/`plugin-host-event` 由可信 iframe 引导显式转换为 Worker SDK 的 `plugin-rpc-result`/`plugin-event`，真实统计、私有保存、UI 与按钮事件都返回。宿主以随机 token、iframe 窗口/端口、实例 ID、插件 ID+摘要+version、调用 ID 与当前授权指纹绑定身份；启动有握手/稳定探测超时，心跳 2 秒、失联阈值 6 秒，超阈值后停止实例并请求浏览器终止 Worker，CPU 循环不阻塞宿主；原生线程回收有额外宽限（[Chromium 源码](https://chromium.googlesource.com/chromium/src/+/HEAD/third_party/blink/renderer/core/workers/worker_thread.cc)默认约 2 秒），实际无限循环验收以最终线程销毁和 CPU 归零为准，不承诺硬实时。停止/禁用/卸载/更新/撤权先取消订阅、挂起请求、关闭端口、终止 Worker 与已跟踪后代、撤销 Blob，再清理 UI，迟到消息/写入按实例世代拒绝。入口即做有界接收：实例维度限制排队条数、队列字节、消息 UTF-8 字节和窗口内消息数，超限有限失败并清空队列/停止；SDK 调用 ID 采用递增序列/有界集合，旧 ID 不会在存活实例上重放。不承诺硬内存配额。
- **事件与数据**：插件可订阅 `current-conversation-changed` 与真实 `StorageService` ACK 后的 `conversation-saved`（复用 `persistConversationMutation` 成功边界）；统计输入只返回当前活动会话最近 300 条已保存 user/assistant 消息的角色与非空白字符数，不接受插件自选 `convId`，不包含二阶段、思考、草稿、设置、其他会话或隐藏版本。插件私有存储按插件实例 ID 强制命名空间，写入走与插件管理相同的可靠保存事务；`saveAll` 返回 ACK 后、提交 live/传播 pending/向插件报告成功前重新验证最初实例、世代、内容指纹与授权，停止/卸载/更新/撤权后的迟到写走现有可靠纠正路径，不向 live 或磁盘复活旧命名空间。已提交的插件设置按事务所有权合并进后续普通 pending 快照，只替换仍停留在旧基线的目标命名空间，不覆盖其他插件的后来更新。保存失败向插件返回错误，不报成功；调用频率、并发、请求/响应字节和键名均有上限。
- **受控 UI**：插件只能提交标题、纯文本和有界按钮（最多 4 个）供宿主渲染；所有文字 `textContent`/转义显示，HTML/CSS/JS 不执行。按钮回调重新验证实例存活、当前授权、按钮存在与渲染时会话；会话切换后需等待插件刷新。管理界面为设置“扩展”面板入口的二级对话框，覆盖导入预览、安装、授权、启用/停止、故障、更新差异、回退、卸载、私有数据导出/明确清除和未安装数据列表；390/1280、浅暗/系统主题沿用既有响应式/对比度规则。
- **网络 RPC**：作为独立 `network.rpc` 能力，默认无网络；manifest 与授权都按精确 `scheme://host[:port]` 和 HTTP 方法登记，启用前拒绝缺失/不一致规则。宿主 `fetch` 只允许授权 origin/方法，`credentials:"omit"`、`redirect:"error"`、`mode:"cors"`、`no-store`，拒绝 `authorization`/`cookie`/`host`/`origin`/`referer`/`sec-*`/`proxy-*` 等敏感头，限制请求头/正文/响应字节与 10 秒超时，撤销/停止中止读流；响应必须通过流式 reader 有界读取，无 `getReader` 且非明确空响应时如实拒绝，不用 `response.text()` 整段读取后再检查。CORS、混合内容与浏览器网络错误如实返回。插件直接 `fetch`/XHR/WS/importScripts/动态 import/远程 Worker/WebTransport/资源/导航/IDB 仍由 CSP/opaque origin 实际阻断，不以覆盖宿主函数冒充隔离。

### 界面与生成行为

- “显示回复头像”默认关闭；开启后助手消息和流式气泡在名称左侧显示对应角色图片，无图片时显示名称首字。群聊按消息 `speaker` 解析，已移出群聊的历史发言者仍可从角色库取图。
- “显示消息 Token 统计”默认关闭；开启后在助手气泡下显示输入、输出 Token 与生成速度。API 返回的 `usage` 无论开关状态都写入对应助手消息；旧消息缺少 `usage` 时不显示也不补写。
- “需要 Cmd+Enter 来提交”默认开启：Cmd/Ctrl+Enter 提交、Enter 换行。关闭后 Enter 提交、Shift+Enter 换行；输入法组合态不得误发送。
- “启用串流”默认开启。开启时发送 `stream: true` 并请求流末尾 usage；关闭时发送 `stream: false`，等待 JSON 完整响应后一次显示。主回复、重生成和二阶段生成共用此设置。
- SSE 与 JSON 共用完成信息 `{interrupted, finishReason, completionReason}`，并绑定发起请求时捕获的 controller。SSE 按任意字节块和 CRLF/LF 行边界解析，只跳过无法解析的单条 `data`；JSON 缺少 `finish_reason` 的既有响应仍按正常完成处理，usage 只读取标准响应根级 `usage`。`finish_reason: stop` 或 SSE `[DONE]` 可正常结束；`length`、`content_filter` 及其他未知 `finish_reason` 均保留原始原因并按未完成处理，不得伪造为 `stop`。EOF 有 `finish_reason: stop` 时正常结束，没有任何终止依据的 EOF 仍为中断；abort 与流式空闲超时分别记录 `completionReason: abort` / `timeout`。reader.read 抛出 AbortError 时即使 signal 尚未标记 aborted 也必须按中断处理。
- SSE `[DONE]` 是立即终止边界：同一网络 chunk 中其后的帧以及后续 chunk 全部忽略，完整 UTF-8 字节在同块或跨块送达必须得到相同结果。DONE 前保留已解析的 `finish_reason` 与 usage；DONE 前的供应商 `error` 帧以及 2xx JSON 错误对象仍进入既有错误分支并保留供应商消息。错误分支不提交错误帧前的部分正文；重生成继续保留原完整回复。中断、截断或过滤但已有正文时沿用部分回复契约：普通生成保存未完成部分，重生成只追加 `interrupted` 候选版本且不替换原有效版本。
- 业务回调异常不得被 JSON 解析容错吞掉；解析器只忽略单条畸形 JSON。onComplete 同步抛错或返回 reject Promise 时，终止回调仍只尝试一次，异常由解析器/请求入口返回的 Promise 交给调用者，不再重派为 onError；未终止的 onToken 同步异常仍只调用 onError 一次。旧响应结束只释放自己的生成 controller，不得清除较新操作的生成、停止或提示词构建状态，也不得用旧 controller 重置新请求的空闲超时。
- T02 独立回归使用原 HEAD 响应解析源码与完整 UTF-8 字节夹具复核：`[DONE]` 在同 chunk 和跨 chunk 均正常结束，DONE 后帧均被忽略；原缺陷是 DONE 前供应商错误被忽略和完成原因缺失，不是 DONE 被误判为中断。初版 T02 候选引入的 DONE 后分块依赖在独立审查中被拒绝并已修正；夹具自身截尾不计为生产缺陷。协调者完整检查（66 项 Python）、独立异常/恢复观察器及两套 Chrome 回归通过，含错误/截断保留、JSON/SSE 一致、EOF/中止 Promise 转接、错误后不再送出文字和正常发送/自动总结，尚未发布。

### 总结与记忆行为

- 自动总结只能在尚未覆盖的普通消息数量达到用户设置的触发阈值时启动；阈值只决定何时触发，触发后继续保留最近消息缓冲。
- 新摘要使用 `summaryVersion: 2` 和 `sourceMessages: [{id, revision}]` 记录生成时来源；`coveredStart/coveredEnd` 保留供范围展示及旧格式兼容，不再单独证明有效覆盖。
- 摘要每次使用时根据当前消息重新核验来源存在、顺序、内容修订与范围完整性；来源匹配为 `valid`，来源记录不匹配为 `invalid`，没有 v2 来源记录为 `unverified`。只有 `valid` 摘要参与模型上下文注入和原文覆盖。
- 自动总结与上下文计数必须按已核验来源在当前消息中的有效区间并集计算未覆盖消息；局部总结、重叠总结或越界旧记录不得把区间外消息误判为已覆盖。
- 聊天页上下文进度只显示尚未被总结覆盖的普通聊天消息数，并与自动总结触发计数一致；SillyTavern 预设、世界书、二阶段消息和空正文不得计入该进度。
- 手动“最近 N 轮”和自定义范围总结只覆盖已核验的实际来源区间，不得按最大 `coveredEnd` 删除范围外的更早消息。
- 只有数字区间的旧摘要保留文本与原区间，标为 `unverified`；不注入模型上下文、不隐藏原文、不用升级时当前修订伪造生成时来源。列表提示建议重新总结；本批不提供将旧摘要直接改为可信的确认入口。
- 编辑、删除或切换来源回复版本后立即重新校验摘要；`invalid` 或 `unverified` 只影响模型使用，不能删除摘要文本或原始聊天。原文仍受原有最大上下文窗口限制，不保证所有历史同时发送。
- 同一会话任一时刻只允许一个总结请求；重复的自动或手动触发不得产生第二个 API 请求或重复总结记录，请求结束或失败后必须释放状态。
- 请求冻结发起会话、来源 ID/修订及输入副本；返回时必须核验仍为原存活会话与原来源。请求期间编辑、删除或云恢复替换目标时拒绝迟到结果，不写入其他会话或重新创建已删除会话。
- 新摘要须先作为待提交候选，等待立即本地写入完成确认后才加入有效覆盖、模型注入或报告完成；模型返回成功、安排写队列或展示候选均不等于可靠保存。请求失败、空结果或保存失败不推进有效覆盖；保存失败移除本次新增候选，并修正写入期间捕获的后续待写快照，不把失败摘要安排为自动上传。
- 总结 API 的非 2xx 响应必须显示 HTTP 状态及供应商返回的错误信息；成功响应不是合法 JSON 时必须明确报告格式错误，不得统一伪装成 `Unexpected API response`。
- 缺少 `summaries` 字段的旧会话在首次成功总结时必须自动初始化总结列表，不得因旧数据结构导致结果无法写入。
- 自动总结失败时必须向用户显示具体原因，不能静默失败；失败后不得按成功状态刷新上下文计数。
- `npm run check` 必须覆盖部分范围裁剪、重叠区间后的自动触发、上下文计数、阈值边界、并发防重、锁释放和 HTTP 错误透传。

### 回复版本与可靠提交（M1）

- 用户、助手和二阶段消息均有稳定 `id` 与内容 `revision`。缺失或重复 ID 的旧消息按会话 ID、原位置与内容修订确定性生成 `legacy-` 身份；已有合法唯一 ID 保留，重复执行规范化不改变结果，同一旧快照可得到相同身份。不同旧快照不按下标强行合并为同一消息。
- `revision` 是角色、正文、思考、发言人、阶段、主回复关联及附件等内容的 `m1:` 指纹与长度，不是计数加一，也不是安全哈希或权限证明。编辑时 ID 不变，相关内容变化后重算修订。
- 重复 ID 涉及的摘要来源标记为歧义，不能成为有效覆盖；二阶段关联按原消息位置修正。新增二阶段消息保存 `parentId` 和对应主回复的 `parentRevision`。
- 主回复重生成目前只支持最近且前一条普通消息为用户消息的主回复；中间历史回复直接提示不支持，原数据不动。请求逻辑排除目标，候选在独立流式区域显示，不先删旧正文或关联二阶段。
- 请求绑定发起会话、目标对象、目标修订及前置消息来源。返回时会话或来源变化则拒绝替换；切换界面不改变写入目标，也不在其他会话显示该候选。

## SillyTavern 卡片运行时兼容

### 宏

- 系统提示词、预设、世界书和历史消息在发送模型前支持常用 SillyTavern 宏，包括角色/用户/用户设定、最近消息、换行、预设提示词以及 `getvar` / `setvar` / `addvar` / `incvar` / `decvar`。
- `random` / `pick` 在同一会话和相同调用顺序下保持确定性，避免重新查看提示词时无故漂移。
- 会话变量保存于会话自身；未知宏原样保留，避免破坏将来版本的卡片文本。
- 宏解析限制输入长度、递归层级和执行步数，防止异常卡片阻塞页面。

### 声明式正则

- 支持角色卡及 SillyTavern 预设的 `regex_scripts`，按显示、用户输入、模型输出、世界书和思考内容等 placement 工作。
- 支持显示/提示词阶段、最小/最大深度、捕获组替换、`trimStrings` 与编辑消息约束。
- 角色卡正则默认关闭，首次导入时必须分别取得授权；角色编辑器可独立控制显示文本和模型提示词权限。
- 预设正则导入后默认关闭，首次导入明确询问，设置页可随时切换；导出时写回 `extensions.regex_scripts`。
- 只允许有长度上限的 `RegExp` 文本替换，绝不执行角色卡或预设携带的 JavaScript。
- 正则执行使用单一可终止 Worker 串行队列：提示词任务优先于显示任务，提示词请求不因显示积压被拒绝；同一替换 key 的显示任务在提示词请求到达时复用并提升优先级，跨阶段共享，取消显示链不得破坏提示词仍需要的任务。
- 显示队列准入上限 256，超出者进入等待队列；等待与待执行显示任务都绑定到当前有效的消息/显示链，新版本文本取代过时 pending、关闭规则/删除消息/切换会话时立即释放等待任务，因此等待队列实际有界，不会随流式刷新或 500000 字符原文逐版本积累；显示容量只影响显示链的准入边界，300 条可见消息仍会全部收敛完成。
- 进行中的任务按替换 key 独立去重，不因完成结果缓存（上限 256）淘汰而重复执行或重复入队；失败结果不缓存，Worker 错误与 500ms 超时后可重试。
- Worker 的下载/初始化与正则执行分开计时：主线程构造 Worker 后先提交 `regex-worker-prepare` 握手请求，Worker 只对该请求回 ready，主线程收到 ready 才提交真正任务并启动 500ms 执行计时，因此装载延迟不计入执行超时；未收到 prepare 时脚本不主动发送 ready，旧标签页（第 11 版及以前）直接提交正则任务仍按原协议在第一条消息返回 result，新发布不会打断旧标签页。Worker URL 带固定版本参数避免部署平台长期缓存旧脚本。装载等待本身有 10 秒上限（`REGEX_WORKER_LOAD_TIMEOUT_MS`），超时明确报“加载失败”，不会无限挂起。Worker 用 `performance.now()` 返回实际执行耗时，正常返回但实际执行超过 500ms 同样拒绝；执行超时提示包含规则 `name`/`scriptName`，缺失时仍正常报错。完成、错误或超时都会清理计时器、终止 Worker 并释放队列，真实执行仍保留 500ms 终止隔离。
- 显示按消息保存当前串联链（流式等没有消息对象的路径按会话保存）：每条规则以上一条结果作为输入，显示积压全部完成后结果稳定、不重复重渲染、也不无限调度；生成期间的显示完成刷新合并并延后至生成结束，避免重建历史销毁流式气泡，等待项只受当前有效显示链数量约束。
- 显示链失效签名采用结构化 JSON，覆盖原文、规则顺序/开关/深度，以及替换参与展开的宏上下文（预设 main/jailbreak 正文、历史最近消息、会话变量、当前消息对应的 MVU 与世界书）；签名不包含 `random`/`pick` 的展开结果，避免每次渲染无限重算；显示替换沿用历史语义，附带当前消息与其对应 MVU。
- 提示词历史消息在格式化前保留内部来源消息、ID、修订和对应 MVU 快照；同步与异步正则替换共用同一上下文，当前模板使用当前数据，历史模板使用各自来源快照，不被宏环境的最新 `mvuData` 覆盖。最终只向供应商发送现行 `role/content`，不包含来源 ID、快照、权限或运行对象。
- 正则结果缓存键覆盖输入、规则、替换结果、来源 ID/修订、MVU 快照、阶段、深度和影响宏的设置摘要；编辑消息、更新 MVU 或切换回复版本后不得复用旧结果。冷缓存同步首调用仍允许返回原文，等待异步刷新完成后同步/异步结果一致；提示词优先、任务去重、失败不缓存、冷缓存异步刷新与取消保护保持不变。
- 关闭规则、删除消息或切换会话后过时链停止后续步骤并释放待执行任务，取消不产生未处理的 promise rejection；复杂规则在没有消息对象的显示路径（流式）仍由 Worker 执行，仅无 Worker 时才退回固定宽度同步替换；显示失败保持原文且不自动重试。
- Worker 启动与继续调度合并到单个微任务，让当前同步 DOM 渲染栈先返回，避免 300 条历史全量重绘阻塞 Worker 消息与 500ms 超时回调造成假超时；显示结果刷新按当前正则批次合并，仅在批次清空（pending 为空）后一次性重绘完整链结果，不因每条规则完成就重建整表。

## 构建与漂移门禁

浏览器加载的 `assets/js/app.js` 由 `scripts/build-app.js` 按 `src/app/manifest.json` 顺序拼接 `src/app` 源分片生成；修改源分片后必须运行 `npm run build` 重新生成 bundle。

`npm run check:bundle`（已接入 `npm run check`）执行漂移门禁：

- 备份现有 bundle 后运行 `scripts/build-app.js` 重建，以 SHA-256 内容哈希比对重建结果与现有 bundle。
- 一致时明确输出同步结论；不一致时恢复原 bundle 并以退出码 1 失败，输出双方哈希并提示运行 `npm run build`。
- 不得改变 `scripts/build-app.js` 的拼接逻辑。

验收：

- 当前仓库状态下漂移检查能得出明确的一致/不一致结论。
- 修改任一源分片且不重建时，检查失败并指明需要运行 `npm run build`。

## ChatGPT Sites 部署

- Sites 构建是现有前端之上的部署层，不得把应用重写成另一套聊天界面。
- `.openai/hosting.json` 只声明 Sites 管理的逻辑绑定；云同步使用名为 `DB` 的原生 D1，不启用 R2。
- `sites.wrangler.jsonc` 与现有 Cloudflare Pages 的 `wrangler.toml` 相互独立，Sites 构建不得改变原部署配置。
- 构建时把 `index.html`、前端资源和公共目录实际引用的角色卡复制到临时目录；不得把 Android、Python 服务端、测试、文档或未引用的重复角色卡打进部署包。
- Sites 版本使用本地编译 Tailwind CSS 和本地 DOMPurify，不依赖运行时 CDN；DOMPurify 使用无已知生产依赖漏洞的版本。
- Worker 必须在 `/` 和 `/index.html` 返回 OpenTavern 入口，并优先返回已打包静态资源；不存在的静态路径才交给 Vinext 路由。
- Worker 必须把所有方法的精确路径 `/api/sync` 交给现有同步后端，并把 Sites 的 `DB` 绑定传入；接口需继续兼容 v1/v2、分块上传、并发保护、健康检查和两种认证请求头。
- D1 schema 以 `db/schema.ts` 为唯一声明源，Drizzle 迁移必须随发布打入 `dist/.openai/drizzle/`；运行时幂等建表仅用于兼容旧部署。
- `dist/server/index.js`、`dist/client/opentavern.html`、`dist/.openai/hosting.json` 与 `dist/.openai/drizzle/` 是发布必需产物。
- `npm run build:sites` 必须同时重建应用 bundle、筛选角色卡资源、编译样式、构建 Worker、复制 D1 迁移并运行 `check:sites`。

- Sites 默认采用私有发布。Preview 与正式站点是不同来源，本地浏览器数据不会自动互通。
- 主模型与总结 API 继续由浏览器直连，目标供应商必须允许 Sites 来源的 CORS；用户自带 API Key 不得升级为全站共享 Secret。
- Sites 原生 D1 提供默认同源 `/api/sync`；新站点需重新填写同步令牌并在导入旧数据后执行“立即上传”。Python 图片网关继续外置，默认同源 `/api/image/generate` 不可用。
- 旧来源的 IndexedDB、OPFS 和 localStorage 不会被发布删除，但新来源无法读取。切换前必须先导出 v3 完整备份或上传云同步；新来源导入后核对会话、角色、世界书和设置，再重新填写本机凭据。
- 新 D1 首次发布为空，不得声称旧 Cloudflare D1 会自动迁入；必须从最完整的旧来源导出、在 Sites 来源导入、主动上传，再用另一设备下载验证。

## IndexedDB 有界等待与本地保存故障恢复（2026-10-31，已发布两端，用户真机恢复观察已记录）

手机 Chrome 访问 ECS 的普通 HTTP 来源时，曾出现发送一直忙碌、输入文字保留、没有用户气泡与模型请求，摘要也停在生成中；该现象为用户观察，未确认附件是否保留。桌面端正常。没有取得真实手机的 IndexedDB 日志，因此不能把根因确证为某个 WebKit 缺陷。已用真实 `sendMessage` / `performSummarization` 加不会结算的持久化 Promise 复现同一失败模式：发送保持输入与锁并零模型请求，摘要成功后永不完成/提交。本次只修复该非结算等待边界。

- IndexedDB 打开与事务使用固定内部期限，不提供用户选项：打开 5 秒、事务 5 秒、可选 OPFS 恢复候选读取 5 秒。普通打开/事务失败（含中止成功的超时）仍保留一次 fresh 重试；中止抛错导致结果不确定时不自动重试。超时本身以明确错误结算，不会被直接改成成功。
- 只在实际使用的 IndexedDB 打开、只读请求、读写完成和清空路径加入期限；现有 `loadAll` / `saveAll` / `clear` 调用方、存储键、快照格式、localStorage 兜底和空快照保护不变。
- 事务超时先请求 `abort`。中止成功时按普通失败结算并允许一次重试；若超时等中止请求下 `abort` 抛错（例如事务已完成时的 `InvalidStateError`），不能宣称旧写入已回滚，也不再自动重试，而是用现有 IDB 读取路径做一次有界只读回读：落盘候选与本次数据一致才确认成功，不一致或回读失败则以明确的“完成结果不确定”错误失败。原生 `onabort` 事件到达时回滚已经发生，不再调用 `abort`、不做不确定回读，原样保留 `tx.error` 的名称/代码/消息（例如 `QuotaExceededError` code 22），继续走既有重试、配额与备份处理。迟到完成/错误/中止回调仍被忽略。
- 打开超时后迟到的数据库只关闭，不接入当前连接；旧 `onclose` / `onversionchange` / 打开错误处理器按连接身份隔离，不能清掉后来建立的健康连接或缓存 Promise。旧打开失败经 `withRetry` 清理时也必须保留更新的 pending `_dbPromise`。
- 最坏等待按阶段有界，不构成整条流程的实时截止承诺：单次“打开+事务”约 10 秒（打开 5 秒 + 事务 5 秒）；默认一次重试使其两次尝试接近 20 秒；保存流程先做快照预读再写入时，两段各按接近 20 秒计，合计接近 40 秒；可选 OPFS 恢复候选读取另加最多 5 秒；中止结果不确定时只额外做一次有界只读回读（需要重新打开时最多约 10 秒），不重试写入。上述计时器随页面挂起暂停，主 JS 线程被阻塞时也无法按其触发，不能承诺跨后台挂起的实时截止。保存路径仍先尝试 IndexedDB，失败后按既有语义写入 localStorage 紧急快照。
- 发送保存失败保留已捕获的输入文字与附件，不改原历史，不产生用户气泡或模型请求，释放 `composerSendInProgress`；附件保留来自合成回归覆盖，手机观察本身只确认输入文字仍在。摘要保存失败保留旧摘要与来源消息，释放 in-flight 锁、按钮和生成状态。后续健康重试必须成功。超时写入不宣称成功；迟到的旧候选不能覆盖后续已接受快照。
- 若超时后中止抛错，但只读回读确认候选已落盘，则按成功 ACK 处理且不重试；只有回读无法确认时才失败。回读不会把已提交数据当作空库，也不会用后续写覆盖已接受的新快照。
