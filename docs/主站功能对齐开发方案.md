### 4.1 公共基础：消息身份与修订

在现有会话消息上追加元数据，不改写原始正文。当前 M1 字段及随后 M3 收藏引用如下：

| 对象 | 当前内容 | 约束 |
| --- | --- | --- |
| 普通消息 | 稳定 `id`、内容修订标识 `revision` | 编辑后 ID 不变、修订变化；用户和助手消息均覆盖；不能只给助手加 ID |
| 二阶段消息 | 自身 `id` / `revision`、`parentId` / `parentRevision` | 沿用阶段关联并规范化；不靠相邻数组位置作为长期关联 |
| 摘要 | `summaryVersion: 2`、`sourceMessages: [{id, revision}]`、派生 `validity` | `coveredStart/coveredEnd` 保留兼容，但不再单独构成有效覆盖证明 |
| 回复版本 | `responseVersions` 中的 `id`、`created`、完整 `message`、`secondMessages`，以及 `selectedResponseVersionId` | 整组保留和切换；中断候选另记 `interrupted`；不把 DOM 内容当数据源 |
| 收藏（M3 已实现） | 会话内 `favoriteMessageIds` 引用目标消息 ID | 不复制正文作为另一份可编辑消息；删除原消息时处理悬空引用 |

修订采用角色、正文、思考、发言人、阶段、主回复关联和附件等内容的 `m1:` 指纹及长度，不是“计数加一”，也不是安全哈希或授权依据。缺失或重复 ID 的旧消息以会话 ID、原位置与内容修订生成确定性的 `legacy-` ID，已有合法唯一 ID 保留；同一旧快照迁移可得到相同结果。内容不同的旧副本不按数组下标强行认同，真实跨设备冲突仍须验证。

当前创建、编辑、删除、重生成、启动恢复、导入和云恢复入口复用身份规范化。重复 ID 的二阶段关联依据原位置修正；摘要来源涉及重复 ID 时标记歧义，不能误判为有效。会话 ID 导入冲突沿用现有备份重映射规则，消息内引用随原会话对象保留。M3 已补充收藏和开场引用测试，实际状态见第 6.1 节。

### 4.2 F01：摘要来源校验

目标：摘要只能替代它真正总结过、且没有被修改的原始消息。

- 请求开始时冻结发起会话 ID、来源消息 ID/修订和本次输入副本；返回时重新核对当前存活会话及来源，不能只依赖早先捕获的对象。
- 摘要分为 `valid`、`invalid`、`unverified`。只有来源仍存在、顺序符合记录、修订匹配的 `valid` 摘要参与覆盖与提示词注入。
- 编辑、删除、切换回复版本后，重新校验关联摘要。失效只影响模型上下文使用，不删除摘要文本或原始聊天；M3 开场切换已沿用回复版本与摘要来源保护。
- 请求期间来源被编辑、会话被删除或云恢复替换时拒绝迟到摘要，不写入其他会话、不重新创建已删除会话，也不假报总结成功。
- 自动触发、进度计数、摘要注入和历史裁剪使用同一有效覆盖结果；保留现有部分区间、重叠并集、最近缓冲和并发防重规则。
- 请求失败或持久化失败不得推进有效覆盖；错误应说明是模型请求还是本地保存失败。
- 摘要作为待提交候选，只有本地立即写入完成确认后才参与有效覆盖或模型注入；生成成功和加入写队列均不能替代完成确认。

旧摘要迁移已采用保守规则：保留文本及数字范围，标记 `unverified`，不参与模型注入或原文覆盖，列表提示重新总结。**不能拿迁移时的当前消息修订伪造“生成时来源”。**本批不增加“确认旧摘要可信”入口；重新总结才建立新来源记录。代价是可能增加上下文或总结 API 成本；原文仍受原有最大上下文窗口限制，不表示全部历史会同时发送。

验收：编辑已总结消息立即失效；删除后不误覆盖下一条；请求途中编辑无错误覆盖；部分/重叠总结计数正确；关闭自动总结不请求，开启后阈值边界只触发一次；旧摘要和原文仍可查看、导出。

### 4.3 F02：回复版本与失败恢复

目标：新回复没有通过校验并可靠保存前，旧有效回复始终可恢复。

- 优先保持旧主回复及关联二阶段数据不动，在独立候选区展示新流式结果；构建重生成请求时逻辑排除目标，而不是先从持久数据删除。
- 固定发起会话、目标消息、目标修订和前置消息来源。返回时目标不匹配则拒绝替换，避免切换会话、编辑或云恢复造成错写。
- 成功后新增回复版本，选择新版本，并一致更新关联二阶段内容；主回复变更后旧选项不能继续冒充新正文对应的选项。
- 候选整组先独立准备与保存；立即写入完成确认前，原有效正文、版本选择和二阶段组保持不变。确认成功且目标仍匹配后才切换当前组，不以先替换后回滚代替此边界。
- 写入前与完成确认后都核验目标。保存期间云恢复替换会话、删除会话或编辑来源时拒绝迟到候选；补偿不能用旧会话副本覆盖新云状态、写入其他会话或重新创建已删除会话。
- 网络错误、取消、空响应、非法格式和存储配额失败均保留旧有效版本。中断但有可用正文时追加标为不完整的候选版本，仍选中原有效版本，不静默覆盖。
- 本批只支持最近且前一条普通消息为用户消息的主回复重生成；中间历史主回复直接提示不支持，不能先删旧消息后返回。
- 版本切换保留完整正文、思考、Token 信息和历史发言人；触发 F01 来源校验，不自动删除后续消息。
- 编辑已版本化主回复或关联二阶段时新增版本，不覆盖原版本快照。主正文修改后旧选项不再作为当前组显示，但仍留在旧版本中；独立二阶段重生成亦保存整组版本，自定义状态栏不强制改成选项格式。
- 首批不增加“自动裁剪旧版本”设置，不静默丢弃历史版本；在大历史样本中验证存储体积和渲染性能。

持久化边界：现有 [persistState](../src/app/state/35-state-persistence.js) 的延迟调用只安排写入，不能把其立即返回当成已经落盘。[会话可靠提交](../src/app/state/35-conversation-mutation-persistence.js) 复用立即写入与错误传播；保存失败在串行队列释放前回滚本次变更，并修正后来捕获的待写快照，拒绝空快照也按失败处理，避免失败候选成为自动上传基线。不另建第二套存储系统。

迟到候选需要纠正持久状态时，只有此前持久层记录与本次被拒绝候选快照精确匹配，才允许对已删除目标纠正空状态；不能放宽正常启动的防空快照护栏，也不能用纠正操作覆盖新的云恢复数据。[存储保存](../src/app/storage/20-storage-service-save.js) 在纠正空状态可靠保存确认后写入既有 clear marker；[快照选择](../src/app/storage/20-storage-service-local-api.js) 排除早于 marker 的旧副本。后续正常保存或显式恢复旧备份，将物理快照 `lastSaved` 提升到至少 `marker + 1`，不改正文或会话逻辑 `updated`，保留 marker 和旧备份。末轮专项已通过；纠正写入或 marker 写入失败会明确报错，不假称已安全恢复，须保留当前数据并重试或导出备份。

验收：失败后原回复/原选项内容及顺序不变；成功后旧版可切回；刷新后版本仍在；二阶段自定义状态栏不丢；切换会话不串内容；保存失败不上传失败候选。已有二阶段“保留旧结果直到新结果成功”的修复必须保持。

## 11. 数据迁移、同步与回退

### 11.1 升级流程

1. 在测试副本验证旧快照，不直接用生产数据试迁移；保存一份可恢复的升级前备份，密钥仍采用现有本机保留方式。
2. 读取旧格式并规范化到内存副本，验证 ID、引用、消息数及原文；没有可靠保存之前不得把迁移当成成功或安排上传。
3. 只追加必要字段，旧摘要文本/范围、卡片未知扩展、usage 缺失和原有设定保持；既有单套预设迁为库的一项。
4. 确认可靠持久化后再启用新字段的业务读写；刷新再次迁移应无变化，不重复生成身份或重复导入。
5. 用两台测试设备完成上传、下载、冲突、加密与重新加载验证，再考虑正式升级。

### 11.2 同步和导入原则

- 沿用现有同步协议与冲突策略，不顺手重做同步系统。服务端存储快照并不保证客户端规范化、合并和导出会保留所有新字段，须逐链路测试。
- ID 冲突重映射必须传递到所有引用。两个设备分别迁移不同旧副本而产生身份分歧时，保留双方数据并明确冲突，不按数组下标强行视为同一消息。
- 没有完成“旧客户端读取、修改、再上传”往返测试前，不承诺混用新旧版本安全。若旧版会剥离新字段，升级窗口内停止旧版写入/自动同步并提示统一升级；需要服务端能力门禁时单独说明变更范围。
- 设置库中的提示词正文、正则等业务字段需要完整同步；本机凭据和沙箱授权不得混入普通设置自动同步。
- 原始请求诊断、搜索索引、流式候选 DOM不进入快照。
- 删除的会话不因迟到 API 返回或旧版本恢复而重新出现。新功能不能绕过现有删除/冲突规则。

### 11.3 回退策略

- 代码回退与数据回退分别处理。回滚前端不保证旧版能理解新增字段；先验证旧版本能安全读取，否则用升级前备份恢复到隔离测试环境。
- 不以清空 IndexedDB、OPFS、localStorage 或删除 D1 数据解决迁移异常。
- 正式回退须保留升级后的新增聊天，不能直接整库覆盖旧备份；先导出两份并进行有确认的合并。
- M4 渲染异常可退回安全文本显示，保留原始内容；MVU 更新失败保持上一有效状态；F19 出错只关闭运行层。
- 换域名不会自动搬迁浏览器本地数据；继续沿用已有导出/导入或经验证的云同步迁移流程，不改变原域数据。

| 测试组 | 覆盖内容 | 放行条件 |
| --- | --- | --- |
| T01 身份与迁移 | 缺 ID、重复 ID、两设备相同/不同旧快照、重复迁移、导入重映射、未知字段 | 原文和消息顺序不变，引用一致；冲突不静默覆盖 |
| T02 摘要 | 开关、阈值前后、部分/重叠覆盖、来源编辑/删除、请求中变更、会话删除、HTTP/JSON/空响应 | 有效覆盖、进度和实际请求一致；失败不推进；旧摘要不伪造来源 |
| T03 生成保护 | 主/二阶段重生成、版本切换、续写；串流/非串流、取消、超时、格式错误、保存失败、切换会话、刷新 | 原有效数据保留，成功结果只提交到匹配目标；不存在错误上传 |
| T04 提示词 | 多预设、笔记/深度/间隔、世界书覆盖、宏预览副作用、后处理、诊断、容量及推理字段 | 实际请求黄金样本一致；关闭新项时默认请求行为不变 |
| T05 聊天操作 | 收藏、搜索窗口外跳转、成员转换、备选开场、用户口吻草稿 | ID 定位准确，历史保留，草稿不误覆盖或自动发送 |
| T06 安全与格式 | 非法 regex、回溯耗时、Markdown/HTML 注入、MVU 非法路径/类型/递归、未知模板 | 不卡死、不越权；非法输入有具体提示，原始内容不被破坏 |
| T07 数据往返 | v3 备份、分项恢复、加密/非加密 D1 快照与增量、两设备冲突、新旧客户端 | 新字段完整，未选项不变，敏感项排除；不兼容旧版明确阻断风险操作 |
| T08 界面与外部服务 | 四档视口、浅暗/系统、键盘、菜单收起、流式长文、模型接口、移动端限制 | 截图与操作证据齐全；未实测服务明确标注，不计入完成 |
